## 本轮解决的问题

### 目录与压缩包读取

目录查询过去主要依靠进程内缓存，重启后深层路径容易再次逐级查询。本轮增加 SQLite 持久索引，保存文件 URI 和目录列表。有效索引可跨重启复用；读取文件时核对元数据，手动刷新、重命名和删除使相关缓存失效。目录列表最多保留 128 个、有效期 5 分钟，URI 最多 32,000 项，避免索引无限增长。

ZIP/CBZ、ZIP64 的 Stored 和 Deflate 页面改为读取中央目录后直接定位条目，不必为跳到后面一页顺序遍历前面的页面。不同 ZIP 页面的直接读取不再共用 RAR/7z 有状态解码器的锁。保留 CRC、展开大小、路径与格式检查；RAR4、RAR5、7z 和其他 ZIP 压缩方式继续走原生兼容通道。

### 打开漫画不再等待保存队列

设置、历史和进度仍按顺序持久写入，读取使用最后一次成功提交的数据快照。目录查询、页地址、打开漫画与图片读取不再等待整条保存队列。保存失败继续报告错误，不提前把未保存状态当成已保存结果。

原生文件读取与数据保存分别加锁；大型目录的 JSON 回复在后台完成序列化。验证时实际锁住数据写入，让保存保持等待，此时漫画页目录和应用数据仍可读取，释放锁后保存正常完成。

### 图片显示核心原生化

界面继续使用 React / TypeScript，静态漫画的图片读取、解码、像素缓存和显示改为 Java 原生 View / Canvas。界面只提交位置、透明度和显示状态，漫画图片字节不再经过 WebView 消息桥，也不由浏览器再次解码。

- 当前页优先，后台预读相邻页；同一图片的并行请求合并。
- 下一页准备好后完整替换画面，等待期间保留当前图片。修复了后台解码完成后未唤醒等待画面的时序问题，并添加受控延迟回归。
- 超大图按显示尺寸采样，放大时仅补充可见区域的高清图块。8000 × 10000 测试图的基础位图使用 8 倍采样，约 5 MB，而不是一次生成约 320 MB 的完整 ARGB 位图。
- 已有同一页缩略图时，超大图先显示该页预览，再后台替换清晰图；不会拿其他页面或整本封面冒充当前页。
- 原生支持 EXIF 的 8 种旋转／镜像方向，以及 Omi 的亮度、对比度、伽马、色温、灰度、反色、锐化与降噪。保留单／双页、全景、左右顺序、音量翻页、双指缩放、双击复位与自动阅读。
- PDF、EPUB 和动态 GIF 保留原兼容显示通道，本轮原生化范围是静态图片漫画。

目录、详情和阅读页面的切换用异步合成快照衔接，不在主线程重新绘制整屏截图。阅读切入和返回采用约 240 ms 的线性滑动，栏目替换约 140 ms；新请求覆盖旧请求，避免旧转场回调把新页面清走。界面与原生图片一起移动，顶部、底部控件仍由 Omi 管理。

### 设置同步

「性能与缓存」保留并说明以下设置：

| 设置 | 当前行为 |
| --- | --- |
| 阅读图片内存缓存 | 默认 100 MB；实际预算同时受设备内存约束，设备上限为应用内存额度的三分之一并限制在 24–192 MB。当前可见图片保留，不能把该值理解成整个应用内存上限 |
| 前后各预加载页数 | 按原设置预读；内存缓存设为 0 时关闭相邻页预读 |
| 图片并发加载数 | 调整为实际支持的 1–4；前台优先，后台预读最多 3 项 |
| 阅读页面磁盘缓存 | 默认 512 MB，可设 0–2048 MB，跨重启复用已解压页面 |
| 封面与预览磁盘缓存 | 默认 128 MB，可设 64–512 MB |

高清图块有独立的 4–24 MB 预算；画面调整结果也有独立的有界缓存。清理磁盘缓存不删除漫画和阅读记录。

安装包包含 arm64-v8a、armeabi-v7a、x86_64、x86；实际运行验证的是 x86_64。Windows 专用源码及已有 EXE／ZIP 与本轮开始时的基线逐项核对，34 个文件内容未变。公共界面文件的原生路径以 Android 环境判断隔离。

ZIP 专项本次样本中，建立索引为 7–55 ms，读取并解码所测随机页为 28–85 ms；2500 页压缩包索引 55 ms。读取测试没有复制整本压缩包。固实 RAR 的首建索引本次为 614 ms，说明固实格式仍存在顺序处理成本，不能把 ZIP 的结果套到所有格式。

性能计时与原始记录见下节。功能测试为了注入真实触摸、等待稳定画面，包含固定等待，因此其 `openMs` / `turnMs` 不用作性能指标。

## 性能测量口径

专用 `native-speed` 测试统计点击到目标阅读页已经解码就绪的时间，以及 20 次已缓存页面切换；不把触摸测试的人工等待算入耗时。此指标不包含约 240 ms 转场全部结束的时间。超大图命中同页预览时，首显就绪也不等于高清细化完成。

测量前清理应用派生的阅读、封面和压缩包缓存，保留授权、SQLite 索引及 WebView 自身缓存；计时前准备页面目录。因此它是固定场景的读页／首显比较，不是清空手机后第一次安装的全流程启动速度。

同一模拟器、相同样本和测量脚本的记录如下。旧版基线为 1.1.11，新版为最终交付 APK：

| 场景 | 1.1.11 | 1.1.12 |
| --- | ---: | ---: |
| 第一本文图目录首显就绪 | 540 ms | 559 ms |
| 8000 × 10000 图片首显就绪 | 178 ms | 164 ms |
| Deflate CBZ 首显就绪 | 180 ms | 209 ms |
| 再次打开文图目录 | 146 ms | 158 ms |
| 20 次缓存翻页，中位数 | 34 ms | 33 ms |
| 20 次缓存翻页，P95 | 36 ms | 50 ms |
| 页面就绪采样中空白次数 | 0 / 40 | 0 / 40 |

这组样本没有证明所有打开场景都比旧版更快，也不支持“数倍提速”的结论。本轮明确验证了保存等待不再阻塞打开、ZIP 直接定位读页、跨重启缓存复用和大图受控解码；原生阅读专项整轮记录的空白绘制帧为 0，受控延迟期间保留了上一帧。超大图的清晰化仍在后台进行，独立解码测量约 0.4 秒。

原生基础位图、缩放图块和界面层的实际显示已检查，截图见 [双页显示](../test-results/android1112-native-double.png) 与 [放大显示](../test-results/android1112-native-zoom.png)。

## 交付边界

本轮完成了读取路径、保存隔离和静态图片核心替换，并通过真实 APK 测试。尚未在用户实体手机及其实际漫画目录上测量；不能据模拟器数据宣称已经达到 ComicScreen 在该手机上的速度。固实压缩包首次远距离跳页、慢速文件提供程序及超大图片的清晰化仍需要实际读取／解码时间。

没有修改 PC 专用功能，没有上传 GitHub，也没有修改用户原始漫画。原有签名与旧安装包均保留。
