## 交互修复

1. **首页点击与长按分离。** 手机轻触不创建「继续阅读」覆盖层，不降低卡片透明度；按住 450 ms 才显示长按入口。手指移动取消计时，长按松手不会再误触阅读。PC 原悬停入口保留。
2. **底栏按位置衔接。** 资源库 → 书架 → 收藏 → 书签 → 最近阅读按这个顺序确定方向；前往右侧栏目时旧页面左移、新页面从右进入，反向则相反。动画约 210 ms，底栏固定，旧页面渐隐。再次点击当前栏目继续执行原有回到目录／顶部行为，并取消过期导航。
3. **目录居中渐变。** 文件夹和书架层级用约 180 ms 的轻微缩放与渐变衔接；等待目录结果时继续保留旧列表。
4. **详情保留封面连续性。** 参考本地 EhViewer 的封面位置变化与内容淡入思路，独立实现约 220 ms 的封面衔接，保留 Omi 配色与布局。按资源身份匹配返回卡片；重命名、筛选或滚动使原卡片不可用时退化为整体渐变，不飞向其他漫画。旧 WebView 使用原生快照回退。
5. **最近阅读增加打开路径。** 长按后的右侧圆形操作加入手绘 SVG 文件夹箭头，打开资源所在目录。只有单文件授权时不猜测父目录授权，而提示加入包含目录。
6. **快速切换保护。** 新导航取消旧捕获与回调；从原生截图转场切到 Web 转场时主动撤销旧截图，避免延迟截图覆盖新界面。减少动态效果设置仍生效。

已查看真实中间帧与 SVG：底栏位置、封面连续性、图标居中及预览选中边框均检查。没有引入新主题或改变现有 Omi 图标风格。

## 读取与画面修复

### 首屏优先于资源库后台工作

性能追踪发现，准备漫画首屏时，仍可见的资源库继续反复检查路径、统计页数和加载封面。Android 现在从读取漫画清单到首屏准备期间暂停这些后台批次；旧列表继续显示、返回仍可用，取消打开后恢复。PC 不启用此暂停分支。

相同测试中，首本打开前的这类桥接请求由 24 次降到 8 次。首次打开耗时有所降低，具体数据和口径见下方对比。

### 预览为何落后正文

旧预览队列在拿到 URL 后就释放名额，实际文件读取与图片解码仍在继续；周边缩略图容易排在选中页前。大跨度拖动后，已离屏的工作也继续占用队列。正文已经进入原生显示，而预览仍走另一条重复读取路径。

本轮为 Android 预览增加独立调度：

- 调度名额持续到图片加载和解码完成；选中页优先于邻居，可打断低优先级前端请求。
- 合并同一页请求，离屏和关闭后取消订阅。拖动时只保留目标附近少量卡片，实测挂载 9 张以内。
- 暂存已解码预览，最多 64 张、8 MiB、60 秒；文件版本变化、刷新或清理缓存会失效。
- 已在原生阅读器解码的正文直接缩成预览，绕过常规预览解码锁，并保存到原有磁盘缓存。EXIF 已旋转的预览有单独标记，避免二次旋转；快路失败回到正常读取。
- 详情中的 Android 缩略图也使用相同调度，离屏未完成请求可取消。

现有设置仍控制阅读内存预算、相邻页数量、并发与磁盘缓存。新增的短时预览暂存是有界内部工作集，未新增要求用户调参的开关，也没有单纯扩大默认阅读缓存。

### 换书后的缓存与任务

原来已有 LRU 淘汰，并非完全没有缓存替换。问题是切换会话后，已启动的预读、清晰化或处理任务仍可能继续并写回缓存。

现在读取前后、解码前后和最终提交都核对任务所属会话；换书缩减旧位图驻留、清理旧图块与处理结果。首屏预热有独立编号，真正进入阅读时可接管同页预热；后一次预热不会误取消已经被阅读器接管的任务。旧任务结束不能清掉新任务的同名标记。大图清晰化中途取消后，重新打开可接续或重新启动，不会一直停留在低清预览。

取消可以阻止旧结果继续解码和回写；已经进入系统文件提供程序的一次读取仍须返回，不能承诺任意介质都即时中断。

### 上半区域颤动

代码中有两条可能产生此现象的路径：WebView 与原生画布反复提交亚像素坐标，以及高清分块逐个发布导致局部反复更新。本轮按物理像素对齐坐标，观察尺寸变化，每个显示帧只采用最新几何消息；高清图块整批发布。

原生测试在上半区域每次比较 828,444 个像素，连续 8 次截图、间隔约 120 ms，变化次数为 0。这个结果证明测试场景的静止画面稳定，不等同于在所有手机上覆盖了全部颤动原因。

## 打开与翻页性能对比

同一模拟器、相同样本和 `native-speed -ColdCache` 脚本，分别测修改前 1.1.12 与最终 1.1.13。清理派生阅读／封面／压缩包缓存，保留目录授权、SQLite 索引与 WebView 自身缓存；计时前准备页目录。统计点击到首屏解码就绪，不包含约 240 ms 转场完全结束；不是首次安装后启动应用的全流程时间。

| 场景 | 1.1.12 | 1.1.13 |
| --- | ---: | ---: |
| 进程内首本普通文件夹打开 | 712 ms | 531 ms |
| 8000 × 10000 大图首显 | 139 ms | 172 ms |
| Deflate 压缩包打开 | 151 ms | 165 ms |
| 普通文件夹复开 | 134 ms | 140 ms |
| 20 次已缓存翻页中位数 | 34 ms | 34 ms |
| 已缓存翻页 P95 | 56 ms | 47 ms |
| 空帧抽样 | 0 / 40 | 0 / 40 |
| 首本准备期间路径／页数／封面调用 | 24 次 | 8 次 |

这一组对比中，首本打开减少约 25%，缓存翻页维持原速度；其他打开场景有小幅变慢，不能据此声称所有文件都提速。换书取消旧任务、缩减缓存和优先预览主要改善积压、长尾等待与稳定性。单次配对测量用于发现问题，不代表实体手机的性能分布；RAR／7z 固实压缩仍可能有顺序读取成本。

[性能对比记录](../test-results/mobile1113-performance-comparison.json)保留两版数据；[最终原始计时](../test-results/android-native-speed.json)包含调用追踪。触摸功能测试有固定等待，其 `openMs`／`turnMs` 不作为性能数字。

## PC 界面与架构评估（未实施）

结论：最值得迁移的是前台读页优先、取消过期任务、减少图片传输复制，以及少量保持位置连续性的 UI；不建议把手机布局或 Android 原生 View 搬到 PC。

| 优先级 | 建议 | 当前依据与预期收益 | 实施约束 |
| --- | --- | --- | --- |
| 高 | 阅读页、选中预览优先；取消旧请求 | `electron/services/archiveService.ts` 的两个工作名额使用 FIFO，缩略图与阅读共享；长队列可能让当前页等后台工作。引入优先级和请求身份能直接改善等待 | 维持并发、解压上限和固实格式约束；不能无上限并发 |
| 高 | 避免整页 base64 经 IPC 多份复制 | `electron/main.ts` 把图片 Buffer 转成 Data URL；可评估受限本地媒体协议／流式响应，让渲染进程直接加载 | 保持路径授权、内容类型、大小限制和错误处理；先测内存与端到端延迟，不直接移植 Java Canvas |
| 中高 | 统一页图与预览的请求身份、过期取消和缓存观测 | 手机本轮将实际解码完成纳入调度；PC 详情预览也可借用此思想，减少离屏工作、旧结果覆盖 | 按桌面可视区调整并发，不能照搬手机固定 2 项与 8 MiB 暂存；增加可重复性能测试 |
| 中 | 持久化并限额保存压缩包索引 | PC ZIP 已能根据中央目录直接定位，当前索引只在内存保留 4 本；跨重启或频繁换书仍可能重建 | 核对路径、大小、修改时间，刷新／重命名／删除失效；不能重复实现已有随机读取 |
| 中 | 卡片→详情的短封面衔接、返回定位 | 手机详情有清晰的资源身份连续性。PC 可加入更轻的局部封面衔接，并保留返回时的卡片位置和键盘焦点 | PC 已有品牌转场与阅读渐变；不再叠加全局横滑，不改变鼠标悬停和快捷键 |
| 中低 | 统一操作图标与最近阅读的打开目录入口 | 手机新增 SVG 已检查笔画、尺寸和居中；PC 可在原右键菜单补同语义入口并统一图标 | 保留桌面右键、常驻侧栏与现有操作区，不搬手机长按底栏 |
| 后续维护 | 分离导航、页面请求调度、平台适配与绘制 | 当前 React/TypeScript 负责 UI，Android Java 负责存储／解码／显示，PC Electron/Node 负责桌面服务。巨大页面组件与本地服务继续增长会增加回归面 | 逐模块提取共享状态与接口，平台分别实现；先行为测试再重构，无需为性能整体重写语言 |

PC 的应用数据读取已经可以直接使用缓存，不等待整条保存队列；不能把手机版先前的保存阻塞结论直接套到 PC。手机底部五栏、全屏横滑和触摸长按菜单也不适合替换 PC 的常驻侧栏、右键和快捷键。

本轮对照修改前快照，PC 专用源码、既有 EXE／ZIP 共 36 个文件 SHA-256 全部相同；共享 UI 的新行为均以手机布局或 Android 环境判断启用。`ReaderPage.tsx` 未改，`App.tsx` 仅给 Android 首屏准备传入后台暂停状态。未构建、替换或发布 PC 成品。[边界核对记录](../test-results/mobile1113-pc-boundary.json)。
