# OmiComic 1.1.9 工作报告

日期：2026-10-14。本轮优先优化手机漫画页面加载，同时完成纯色主题、数字排版与拖拽预览修正。

## 漫画加载

已读的 ZIP／RAR／7z 图片页面现在保留在应用私有磁盘缓存中。回翻、离开后再次打开、重启后续读，都可以直接读取缓存，减少重复解压。缓存保存图片文件字节，不保存整本解压目录，也不把全部页面常驻内存。文件身份变化时使用新缓存；没有修改时间的文件提供程序只在当前进程内复用。

阅读页面地址请求使用独立队列，不再排在保存进度、读取书库元数据之后。已缓存的封面与预览可直接返回，不等待另一本固实压缩包的预览解码。页面媒体地址允许 WebView 缓存，显式刷新或清理时更换版本，避免继续使用旧内容。

缓存满时一次清理到预算的 85%，留出后续写入空间，减少反复遍历、排序目录。缓存文件使用临时文件加原子替换，减少逐页写入的同步等待；阅读记录仍使用原有可靠写入方式。启动时在后台载入缓存设置，不在界面主线程扫描缓存目录或重复解析用户数据。

设置入口：**应用设置 → 性能与缓存**。

| 设置 | 默认值 | 可调范围 |
| --- | --- | --- |
| 阅读页面磁盘缓存 | 512 MB | 0–2048 MB；0 关闭此磁盘缓存 |
| 封面与预览磁盘缓存 | 128 MB，原为 48 MB | 64–512 MB |
| 阅读图片内存缓存 | 保持 100 MB | 0–500 MB |

页面显示两类磁盘缓存的实际用量，支持清理；清理不删除漫画、阅读记录或目录索引。原有预加载页数与图片并发设置保留。

## 漫画加载验证

使用同一 Android 15 x86_64 模拟器，对比 1.1.8 与最终 1.1.9 APK。测试文件为自行生成的中性图片，每本 64 页、每页 512×768，分别打包为 ZIP、固实 RAR、固实 7z；单本约 75 MB。没有修改用户漫画。

下表为一次对照采样，单位毫秒。页面耗时包含原生取图、读取响应及浏览器图片解码；不包含用户点击动画。复开后按第 1、32、33、1、64、32 页读取，取六次平均值。每轮冷启动测试前清除派生缓存。

| 格式 | 建立页面列表：旧 → 新 | 首张图片：旧 → 新 | 复开读页均值：旧 → 新 |
| --- | ---: | ---: | ---: |
| ZIP | 284 → 25 | 120 → 69 | 75.3 → 93.0 |
| 固实 RAR | 1105 → 746 | 85 → 77 | 182.7 → 78.8 |
| 固实 7z | 19 → 26 | 74 → 82 | 106.0 → 72.5 |

本次样本中，RAR、7z 复开读页更快，ZIP 复开读页没有提速；不能据此宣称所有格式、所有首次打开都更快。首次读取未缓存的固实压缩包仍受格式顺序解码影响。主要收益是避免已读页面的重复解压，并减少阅读请求的排队等待。

缓存机制的独立验证结果：

- 三种格式重启后各读取 3 页：**9 次磁盘缓存命中、0 次页面重新解压、0 次索引重建**，全部完成实际图片解码。
- 改为 768 MB 阅读／192 MB 封面预算后重启，两个数值正确保留并在原生层生效。
- 100 KB 测试缓存连续写入 180 次，只发生 32 次目录扫描；用量不超限，缩小预算立即生效。
- 占用冷预览解码锁时，已有封面仍可返回；占用数据写入锁时，页面地址请求仍能完成。
- 整本压缩包复制量为 0；测试后恢复默认缓存预算。
