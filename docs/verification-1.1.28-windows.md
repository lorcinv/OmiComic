## 主界面图案使用方式

入口为 **设置 → 外观与主题 → 主界面图案**。点击“选择图片”，在裁剪窗口中调整位置、比例和宽高，确认右侧预览后点击“保存图案”。已有图案可通过“调整裁剪”重新编辑，也可“恢复默认”。

程序保存图案及用于重新裁剪的源图副本。移动原文件后仍能显示和重新裁剪，重启后保留结果。选择文件只进入编辑，保存前不会覆盖已有图案。

支持 PNG、JPG、WebP、BMP，单文件不超过 20 MB、4000 万像素；导入副本最长边不超过 2400 像素，裁剪尺寸按该副本计算。这些限制仅针对首页装饰图案，与漫画原图读取无关。

## PC 加载优化与实测

检查发现，旧配置仍可能保留 500 MB 缓存、5 页预读、5 路加载。图片读取还会把整张图转换为 Base64 长字符串跨进程传递，产生额外复制；ZIP 校验和读取队列也存在开销。本轮分别处理这些瓶颈。

PC 现在通过授权图片地址传输原始字节，预读同时完成图片解码，并复用已准备的图片。ZIP 使用原生 CRC 校验，目录索引和相同页面请求合并复用；后台任务为当前页保留读取通道。

这台电脑可用物理内存约 31.84 GiB、16 个逻辑线程，自动模式为 **4096 MB 图片缓存、48 页预读、12 路加载**；高性能模式为 **8192 MB、96 页、16 路**。缓存值是图片预算，不代表程序会立刻占满这些内存。旧版恰好为 500 MB／5 页／5 路的配置首次升级时迁移到自动模式，其他自定义值保留；迁移后仍可手动修改。

性能对比使用同一台电脑的 1.1.27 与最终 1.1.28 程序，各启动三个独立进程，取中位数。计时包含页面读取和图片解码，保持原图字节与尺寸；未清空 Windows 文件缓存，因此这些数据不代表磁盘完全冷启动。

| 场景 | 1.1.27 | 1.1.28 | 耗时减少 |
| --- | ---: | ---: | ---: |
| 约 30 MiB、4800 × 4800 PNG，首次读取并解码 | 705 ms | 306 ms | 56.6% |
| 5 张大 PNG 并行读取并解码 | 2366 ms | 352 ms | 85.1% |
| 638 MiB ZIP 内首张 3500 × 5200 图片，读取并解码 | 312 ms | 91 ms | 70.8% |
| 同一 ZIP 内 5 页并行读取并解码 | 1346 ms | 261 ms | 80.6% |

补充使用实际阅读器连续翻动六张大 PNG：预读 5 秒后，从点击“下一页”到新图片元素就绪，旧版五次为 280–461 ms，新版为 2–3 ms。测试窗口隐藏运行，绘制回调仍可能被系统延迟，因此这里只记录图片就绪时间，不将其作为屏幕呈现延迟。

原文件只读使用，测试没有改动漫画。原始读取、传输与显示保留分辨率；锐化、降噪的独立处理预览继续沿用已有像素预算。

## 验证结果

- 类型检查、前端与 Electron 构建、Windows 免安装包构建通过。
- 核心测试：93 项通过，1 项按平台条件跳过，0 失败。跳过项为 Windows 不支持的字面通配符文件名场景。
- 组件测试：87 项通过。
- 浏览器回归：57 个不同用例全部通过，覆盖四套主题、裁剪与取消、固定羽化光效、四类中键排序、标题复制、实时调整、阅读预读、文档阅读及手机浏览器回归。
- 从最终 ZIP 解压并运行实际 1.1.28 EXE，七组验证全部通过：格式与持久化、阅读布局、阅读工具与重启、资源库连续滚动、大图封面、首页图案、桌面图片传输。
- 首页图案验证覆盖 PNG／WebP、实际 300 × 200 裁剪、取消和非法裁剪、原文件移动、重启恢复、保存源图再次裁剪及恢复默认。测试指定文件选择窗口返回的路径，后续文件读取、解码、保存和显示均使用最终程序。
- 图片传输验证覆盖原始字节一致、并发请求合并、旧图片失效、未授权路径拒绝、过期阅读会话，以及跨域图片的实时滤镜与画布处理。
- 包内 210 个前端文件和 3 个桌面运行文件与最终构建逐文件一致。ZIP 共 36 个条目，不含用户资料或测试数据。

手机自动阅读测试曾因忽略工具栏三秒自动隐藏而失败；在旧版 1.1.27 中也复现。修正测试步骤后，六项手机浏览器用例通过，没有为此修改手机交互逻辑。本轮未重建 Android APK，Android 成品仍为 1.1.23。

运行验证使用独立测试目录和资料，保留工作目录原有修改。修改前快照位于 `.cache/pc-polish-1.1.28-baseline`。本轮未提交或上传 GitHub。
