# 1.1.72 PDF、MOBI 与栏目位置修复

2026-11-02，Asia/Hong_Kong。基于 1.1.71 的累计工作区修改，编辑前快照在 `.cache/omi1172/before/`。保留旧包和其他未提交修改。

## 问题与处理

1. PC 缩略预览箭头原先使用文字字形，字形基线造成视觉偏移。改用既有 SVG 箭头，并在按钮内水平、垂直居中；七种缩略图列数下验证图标中心。
2. PDF 资源清单最初只有文档占位，详情页又沿用了“文档不提供缩略预览”的判断。详情页现在建立 PDF 预览源，读取实际页数后交给连续缩略预览组件。返回或切换资源时取消并释放文档，阅读器打开期间暂停详情缩略图任务。
3. 手机从缩略图子节点接管触摸捕获时，子节点冒泡的 `lostpointercapture` 被误判为整个拖动结束，导致只移动几个像素。现在只处理预览条自身、同一手势的捕获丢失和取消事件。保留松手即对齐及自身翻页回报不触发二次回中的逻辑。回归新增实际位移断言，避免只检查“是否居中”而漏掉根本没有移动的问题。
4. 现有 MOBI 解析依赖已经支持 KF8，应用自己的前置检查却直接拒绝 KF8 与双格式。本版按书目版本和双格式边界选择传统或 KF8 解析，异步读取章节后继续使用既有内容清理和资源限制。没有新增依赖；DRM、HUFF/CDIC、256 MiB 文件与 8 MiB 文本等既有限制保留。
5. 详情缩略图按离可见区域的距离排序；PC 后台图片解码继续保持单任务，当前预览可越过尚未开始的封面任务。关闭详情时取消等待任务，避免已离开页面继续占用队列。正文的原图与画质处理不变。
6. PDF 共用应用级解析 Worker，文档各自管理传输和页面；关闭一个文档不会销毁整个 Worker。封面出现或发出打开意图时提前准备 Worker，减少进入详情和阅读时的重复启动。没有复用已关闭文档的页面对象。
7. 两端按栏目分别保存路径、书架分类、书架、筛选、排序、页码与滚动锚点。返回其他栏目时恢复有效的位置；再次点击当前栏目使用原有回顶层逻辑。失效的目录和书架不强行恢复。
8. Android 使用系统 PdfRenderer 直接生成首张小封面，按文件身份与版本写入磁盘缓存，失败时保留 PDF.js 回退。PDF.js 生成的 JPEG 封面另存有界 IndexedDB 缓存，最多 96 项、每项不超过 512 KiB；文件版本变化和显式清理都会失效，缓存失败不影响正常显示。
