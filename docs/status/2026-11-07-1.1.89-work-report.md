# OmiComic 1.1.89 安卓放大拖动修复

2026-11-07。Android 1.1.89，版本码 10189；沿用原签名，可覆盖安装。Windows 保持 1.1.88，原安装器与便携包一并放在交付目录，文件内容未改动。

## 问题与修复

用户反馈 PC 正常，安卓 PDF 放大后拖动卡顿，压缩包也有轻微卡顿。本轮只修改 Android 原生阅读绘制，前端手势、Windows 代码和惯性参数保持原样。

旧版等视野超出已解码区域后才准备下一块高清画面；等待时保留上一帧，所以 PDF 解码越慢，拖动越容易停住再跳过去。PDF 还会按图片的二次幂采样等级生成多余像素，并在每次区域绘制后关闭页面。

- 视野接近高清区域边缘时，提前准备移动方向上的下一块。当前区域继续使用到边缘，再整块切换；提前完成不会抢先替换画面，避免反向拖动重复绘制。
- PDF 按实际屏幕像素向上取整到稳定的绘制等级，保留当前视野所需清晰度，减少多余像素。压缩图片继续使用原来的采样规则。
- 连续绘制同一 PDF 页时短暂复用页面上下文；绘制空闲约 1 秒后异步释放。切页、退出、内存回收及关闭文档均处理释放，没有新增整页位图缓存。
- 保留正文与细节共用的缓存预算，细节上限仍为 48 MiB。区域规划同时检查 PDF 单次 600 万像素上限，防止平板上预算允许、实际绘制却拒绝的区域退回不够清晰的底图。
- 缩回适应窗口后，停止请求旧放大区域的预读。

## 同机对照

Android 15 / WebView 124 专用模拟器，同一份 64 页素材。手机为 1080×1920、420 dpi，平板为 1600×2560、320 dpi 横屏。大图压缩包与 PDF 使用同一份 3200×4800 合成图；另测 800×1200 普通压缩图片。两版均等放大画面准备完毕后，再做四次相同的原生触摸拖动与换向。

表中是四次拖动累计等待高清区域的时间，单位毫秒，按原生显示回调采样。它不是平均帧率，也不是实机速度承诺。

| 场景 | 格式 | 操作 | 1.1.88 等待 | 1.1.89 等待 |
| --- | --- | --- | ---: | ---: |
| 手机竖屏 | 大图压缩包 | 普通阅读 | 267 | 0 |
| 手机竖屏 | 大图压缩包 | 纵向全景横拖 | 699 | 167 |
| 手机竖屏 | PDF | 普通阅读 | 1318 | 483 |
| 手机竖屏 | PDF | 纵向全景横拖 | 4215 | 1901 |
| 平板横屏 | 大图压缩包 | 普通阅读 | 1382 | 851 |
| 平板横屏 | 大图压缩包 | 纵向全景横拖 | 0 | 0 |
| 平板横屏 | PDF | 普通阅读 | 3933 | 3000 |
| 平板横屏 | PDF | 纵向全景横拖 | 0 | 0 |

普通尺寸压缩图片两版均没有高清区域等待。累计等待改善不代表每项停顿指标都改善：手机 PDF 全景最长位置更新间隔为 750 → 866 毫秒，平板大图压缩包为 350 → 483 毫秒；本轮没有证明最差停顿在所有场景都变好。较大的 PDF 仍可能出现短暂停顿，本版减少了等待，未将压力测试描述为完全无卡顿。软件模拟器的绘制和纹理解码开销与真机不同，尚未在用户手机或实体平板复测。

## 验证

- 最终 APK：12 个放大拖动场景、48 次长拖动；3681 次原生显示回调检查通过，没有空白画面或高清覆盖不足，动态细节缓存与最终共享位图缓存未超预算。
- PDF 空闲释放检查通过，静置后保留的 PDF 页面上下文为 0。
- 原生区域规划检查通过，覆盖小幅平移、连续缩放、越界换区、采样清晰度和两块区域的内存预留。
- 手机竖屏、平板横屏共 12 个惯性场景通过：松手继续移动、按下止动、停顿后松手精确定位、避免惯性误翻页。
- 12 个全景回归场景、84 次快速翻动通过，检查快速翻页回滚、模式切换位置稳定和原生画面连续性。
- 类型检查、Android 编译、原签名检查通过；安装版本为 1.1.89 / 10189。安装中的 APK 与交付 APK 哈希一致，419 个网页资源与构建目录逐个一致。
- Windows 手势及共享前端文件与本轮开始时逐字节一致；Windows 包沿用 1.1.88，并校验复制前后的 SHA-256，本轮未重建 Windows。

验证中曾发现平板候选包的区域超出 PDF 单次绘制上限，已修复并重跑最终包。另有一次惯性测试因主动停止旧候选包而中断，不计入通过结果。
