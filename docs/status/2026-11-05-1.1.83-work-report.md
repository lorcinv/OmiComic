# OmiComic 1.1.83 工作报告

本次处理八项阅读与交互问题，Android 与 Windows 同步更新至 1.1.83。保留既有阅读模式、滑页手感、手机布局和旧交付文件。

| 问题 | 修复结果 |
| --- | --- |
| 大 MOBI 快速跳页失败 | 移除“同时最多两项请求”的直接报错，改为顺序解析、当前目标优先、预览排后。超时从实际开始解析计算；关闭书本时释放等待中的请求。 |
| 平板 PDF 拖动时卡顿 | PDF 底图按应用窗口尺寸直接绘制，上限 600 万像素并受原有总缓存预算约束。避免适应屏幕时重复补绘高清区域和首次拖动时生成多级纹理；忽略旧版保存的 PDF 图片等级。预览复用正确的正文地址，小预览仍按小尺寸处理。 |
| PC EPUB 跳页闪烁 | 保留旧页，等待目标页的图片、字体、主题和绘制准备完成后再切换。目标文字页提前以不可察觉的透明层参与绘制，避免隐藏 iframe 到显示时才开始绘制。 |
| 放大后点击不能翻页 | 安卓触摸与桌面鼠标均可点击翻页；实际翻页前恢复为原尺寸。保留双指缩放、拖动和中心双击复原。 |
| 安卓按钮透明度设置缺失 | 在安卓“设置 → 漫画阅读设置”恢复“上/下一篇按钮透明度”，范围 20%–80%；取消原样式的 45% 下限，触屏不再套用鼠标悬停高亮。 |
| 漫画卡片点击反馈不明显 | 整张卡片显示约 10% 透明度的主题色蒙版，松手后短暂停留并平滑淡出。滚动时取消，其他手指的移动与抬起不会误清除当前反馈。 |
| 非阅读界面可随意缩放 | 关闭安卓网页容器的页面缩放，并固定应用视口。阅读器自己的缩放和系统无障碍放大继续保留。[WebView 官方设置](https://developer.android.com/reference/android/webkit/WebSettings#setSupportZoom%28boolean%29)。 |
| 手机与平板系统时间栏 | 手机阅读工具栏收起时一并隐藏状态栏；平板横屏默认隐藏状态栏。边缘下拉使用安卓原生临时显示，半透明覆盖内容，阅读区域不跟着移动；后续系统下拉操作由系统处理。[Android 官方行为](https://developer.android.com/develop/ui/views/layout/immersive)。 |

## PDF 卡顿的原因

这次不是安装包体积不足。文件大小主要反映存储量；单页图片解码、复杂图形和字体绘制、位图上传，以及首次生成高清补绘层，决定了拖动时的开销。缓存和纹理准备好之后，同一页就会变得流畅，因此小 PDF 也可能比大 PDF 更卡。

1.1.82 的图片采样规则用于 PDF 时，部分页面会先生成偏小的底图，再在适应屏幕状态补绘更大的区域。本次直接生成足够覆盖窗口的 PDF 底图，并保留放大后的按需细节绘制，避免用重复处理换清晰度。手机图片与 EPUB/MOBI 的既有采样路径继续沿用。

## 验证

- Android 15 / WebView 124 模拟器，覆盖平板横屏、平板竖屏与手机尺寸。验证快速跳页、图片页与文字目录页、缩放后点按翻页、卡片反馈、界面缩放限制、状态栏隐藏和退出后的恢复。
- 421.6 MiB 的《葬送的芙莉莲》执行 11 个重叠章节请求及 6 次连续进度跳转；验证最后目标确实绘制，未出现加载失败。
- PDF 使用图片型样本、约 630 KiB 的复杂矢量样本、普通文字样本，以及用户约 569.9 MiB 的《大地巡旅》原文件。前三组连续拖动合计 12 次，用户 PDF 连续拖动 5 次。
- 在测试中写入旧版 PDF 缓存元数据，确认新版不会继续复用它；原有图片缓存继续保留。
- 改变系统边距时检查转场截图的实际绘制比例，横纵均保持 1，避免收起时间栏时把上一屏拉伸。
- 手机和平板完整流程覆盖 PDF、文字 MOBI/EPUB、图片 EPUB、漫画 MOBI、长图 EPUB 和大尺寸图片：详情预览、阅读、单/双页、方向、连续模式、缩放、退出和续读。
- Windows 实际打包程序验证三本用户原文件及两个自制样本的打开、翻页、书签和重启续读。
- 自动检查：139 项核心测试通过、1 项跳过；243 项界面逻辑测试通过；47 项阅读与手势检查通过（含定向复查及 PC 窄窗口）；当前浏览器与 Chromium 100 各 28 项兼容检查。
