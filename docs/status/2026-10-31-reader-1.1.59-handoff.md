## 根因与修复

| 范围 | 实际问题 | 本版处理 |
| --- | --- | --- |
| 双端普通图 | 1.1.58 高斯低通保住黑白极值和网点均值，却降低细线对比度 | 删除高斯分支，普通图统一 Lanczos3，滤波宽度 0.9；保留灰度、透明度、对称核与重复行复用 |
| PC GPU / 软件 | 两套滤波定义分离；软件首条带没有读取，出现顶部黑带 | 两条路线共用 `samplingWeights()`；GPU 上传预计算权重，移除逐像素三角函数计算；首条带状态改为 `-stripHeight` |
| PC 页面交接 | `allowOriginal` 把“原图可见”误当成“最终滤波准备好”，提前显示后再换画质 | `pending` 只决定是否隐藏，`prepared` 单独表示最终状态；Reader 按真实准备状态交接 |
| PC 双页缓存 | 预算先留前后各一张，随后装更远的前页；上一组只剩半组，无法保留其显示表面 | 按阅读器真实配对计算相邻完整组，优先两侧整组，再装远处页面；不提高预读字节上限 |
| Android 正文 | 原生 PNG、PNGJ 和备用处理有重复实现；1.1.58 派生缓存继续返回软化结果 | 共用 `DisplayResampler.Stream`，删除未使用的 prefilter / filter / fastReduce；派生键 v4 → v5，统一读取、存在检查和写入 |
| Android 放大 | 原生区域没有额外滤波，却仍用 filterBucket 做缓存键；细微移动会重复解码，旧预算限制常使底图持续放大 | 删除无效 bucket；四边按 sample 对齐；底图超过原像素密度即请求清晰区域 |
| Android 预算 | 高清新旧区域占用与预读正文分开计费，当前细节可用空间不足 | tile 上限为 `min(48 MiB, max(4 MiB, 总预算/2))`；正文淘汰按正文 + tile + display 合计，优先淘汰预读，保留新旧区域双缓冲约束 |

## 统一后的显示链路

| 场景 | Windows | Android |
| --- | --- | --- |
| 普通图适屏 | 原始图片解码 → Worker 一次显示采样 → 有界显示 Canvas；GPU / 软件同核 | 原生解析或 PNGJ 逐行解析 → 同一 Lanczos Stream → 适屏 Bitmap |
| 大图 | 单页 ≥5 MiB、>1600 万像素或长边 >8192 时跳过全图自定义采样，保留原图 | 同一大图判定，使用系统有界采样解码，不进行整图 Java 卷积 |
| 放大 | 从原图重画当前可见区域，禁止放大适屏低清副本当最终图 | 独立 details 队列读取原文件可见区域，100 ms 安静期后补图；新旧质量完整交接 |
| 快速移动 | 已完成画面保持；URL 任务可离屏准备，目标页优先 | 原生画面跟随最新几何位置；正文、细节、预览各自有队列和预算 |

“原生读取”不等于无条件把整张超大图完整解码到手机内存。大图仍需预算和局部区域；否则会从模糊问题退回卡死或内存溢出。普通缩小需要适量抗混叠，100% 和放大需要源像素，不能用同一张小图承担两者。

## 验证原则与失败诊断

新增中性细字、1–3 px 细线、硬边、白色页边、透明度和网点样张。50% 缩小的 2 px 细线对比度从 1.1.58 的 128 恢复至约 210，80% 和 95% 从约 178 / 200 恢复到 255。GPU 与软件平均像素差约 0.02–0.04；PNG 原生解析与 PNGJ 同核结果一致。原像素读取还要检查像素相同，不能只看尺寸。

不能把去摩尔纹或黑白最大值正常当作细节清晰。不能只测单页预读：本轮双页回翻在新增回归中曾达到 537–623 ms 且重新启动三个任务，修复整组优先后为约 5–14 ms、零重采样任务、无空帧。该数值只代表已预读的中性页面，不是大型 ZIP 冷读耗时。

Android 手势初测还有独立的测试环境问题：系统 WindowManager 反复等待模拟器 `starting_reveal` 动画超时，使 UiAutomation 的单击变成约 5095 ms 长按。全关系统动画又会启用 WebView reduced-motion，无法检查恢复动画。因此恢复原设置，只把异步手势测试的单击改为系统 `input touchscreen tap`，仍经过真实触摸命中和应用处理；双指、拖动、双击继续保留原生注入。没有修改产品的短按阈值或跳过交互断言。成功记录和超时日志均保留，旧失败日志不能冒充最终通过证据。

首尾拖动测试还发现原生注入已确认、WebView 尚未收到 pointermove 时就读位置的竞态，第一次得到相同的两次偏移。测试增加“实际收到对应指针坐标”后再读几何，原有阻力阈值不变，复测偏移 18.1309 → 31.205，通过。产品滑动阻力没有改动。测试结束已核对系统动画设置完全恢复，并正常关闭本轮启动的 `emulator-5680`，保留模拟器数据。

## 接手步骤

1. 先核对 `docs/COORDINATION.md`、分支、HEAD 和工作区差异。两个账户按文件分工；不要同时修改 `ReaderPage.tsx`、版本号和构建目录。
2. 同工作区直接继续，不要重套补丁；另一份干净基线用源码 ZIP 或先 `git apply --check` 后套 handoff 内补丁。补丁相对上述 HEAD，包含 1.1.56 以来累计交付修改。
3. 清晰度问题先确认运行版本确为 1.1.59、是否使用 v5 派生缓存，再查 ordinary/native 路由、source/target 尺寸、source decode 和 display prepared；不要继续加滤波开关。
4. 速度问题按目录/ZIP 读取 → 图片解码 → 显示采样 → 呈现分段测量；只优化实际瓶颈，不取消前台优先、取消语义、内存边界或整组就绪约束。
5. 手机久糊先查 details 的 sample、可见区域字节、tileBudget、排队和失败计数；不要恢复整图逐像素处理，也不要把预览小图当正文清晰层。
6. 重跑 typecheck、core、DOM、针对性 UI、两端实包；必须同时看细线/文字与网点、单页与双页、冷页与预读页。再更新本报告和 SHA 清单。
