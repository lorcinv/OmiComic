# OmiComic 1.1.87 工作报告

2026-11-07。Android **1.1.87 / 10187**，沿用原签名，可覆盖升级；Windows 成品保持 1.1.85。本轮完成本地修复、构建与验证，没有提交、推送或公开发布。

## 修复内容

| 用户反馈 | 原因与处理 |
| --- | --- |
| 全景快速翻页会回滚 | WebView 的末次移动可能先外推，松手再校正。1.1.86 以 12 CSS 像素区分方向，较大的校正仍会被当作反向甩动。现在由按住时的轨迹决定释放方向，反向的松手校正不再把页面拉回；主动反向、停住再松手和按下止动继续保留。 |
| 切换全景时颤动 | 切换先按旧窗口排版，再因顶部挖孔区域展开而移动、缩放。现在固定切换前的完整画面，待窗口边界、网页布局和原生像素准备好后一次显示；关闭全景同样处理，重复点击有保护，退出阅读会取消旧切换。 |
| PDF 快速滚动比压缩漫画卡顿 | 普通适应窗口的 PDF 底图小于全景所需尺寸，滑动中反复补绘局部；PDF 也没有复用压缩漫画的方向预读调度。现在按横向适应高度、纵向适应宽度准备页面，并优先读取前方页面、取消过期任务，减少重复绘制。 |

PDF 保留原有内存预算、页面像素上限和放大后的清晰区域绘制。普通阅读仍采用原尺寸策略。EPUB ZIP 读取器、原生画面核心和手机安全区域样式与 1.1.86 的文件摘要一致；既有启动优化及顶部空间利用继续保留。Windows 安装器和便携包的摘要也与原交付清单一致。

## 复现与前后对照

旧包为已交付的 1.1.86。使用同一 Android 15 x86_64 模拟器、WebView 124 和合成书籍，未读取个人漫画。

- 每组从第 21 页开始连续快滑七次，第七次加入 40 CSS 像素的反向松手校正。旧包六组中有 5 组出现回滚；新版四种尺寸配置共 24 组、168 次快滑，均未检测到回滚。
- 旧包手机横向 CBZ 切换过程中，原生记录出现五种无遮挡位置／尺寸；新版只保留切换前后两个稳定状态。最终包同时验证关闭全景、重复点击和切换中返回。
- 同一 64 页 JPEG 内容分别包装成 CBZ 与 PDF。下面记录七次相同快滑输入期间 PDF 额外局部绘制的次数；该组不加入松手校正，避免将旧版回滚带来的额外工作混入对照。

| PDF 方向 | 1.1.86 | 1.1.87 |
| --- | ---: | ---: |
| horizontal | 30 | 11 |
| vertical | 0 | 0 |
| rtl | 52 | 10 |

原始对照为 `验证/baseline-phone.json` 与 `验证/final-phone-performance.json`。这些次数反映减少了重复工作，不是所有 PDF 的速度倍率；普通模式已缓存的小底图在刚进入全景时仍可能补绘。软件渲染模拟器的帧耗时受系统负载影响，本轮不将它换算为真机帧率或“与压缩包一样流畅”的承诺。
