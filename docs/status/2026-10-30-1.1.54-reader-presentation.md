# OmiComic 1.1.54 工作报告

本次处理阅读界面的画面交接、全景对齐和手机放大分页，交付 Windows x64 安装程序与 Android APK。保留此前的缩放按钮常态／选中色、纯文字显示和比例标签间距，未替换正在运行的已安装版本。

## 问题与修复

| 问题 | 查明的原因与处理 |
| --- | --- |
| PC 单页／双页往返翻页闪烁 | 已复现准备状态的生命周期回归：页面卸载时画布被释放，但父层仍保存该页“画面已处理”的标记，再返回时会显示尚未准备的新画布。现在卸载和重新准备时同步撤销标记，目标页具备实际显示画面后才交接。前序“保留上一组，等下一组准备好”的优化继续使用，补齐了失效处理。 |
| 全景点击进度条后比例残留 | 旧对齐读取动画期间的可视边框，可能把临时 97% 缩放写入画布的最终尺寸。改用不含祖先动画缩放的布局尺寸；跳转结束后重新对齐。横、纵全景均覆盖。 |
| 全景拖动轻颤 | 处理了会改变画面尺寸和取样相位的路径：布局对齐不再读取临时动画尺寸，运动中迟到的取样结果不替换已有画面，最终尺寸、像素和映射一起交付。保留已有物理像素对齐、连续位移和原生等待邻页时跟随手指的优化。新增检查验证慢拖时固定页面的宽高、垂直于拖动方向的位置保持稳定。尚未复现的真机轻颤不能仅凭模拟器数据归结为同一原因。 |
| PC 放大后右侧多余滚动条 | 自由放大期间隐藏阅读区的原生滚动条，继续使用已有平移和手势。适宽／原图模式在默认缩放下的正常滚动保留。 |
| 手机全景末端来不及显示 | 发现已完成的预读结果在运动中仍可能等待最多 120 ms 才发布，且全景未接入原生缓存的近页排序。Android 改为 32 ms 合并发布，缩小时扩大运动关键页范围，并按视口距离更新原生缓存优先级；这个更新不改变请求代号，不取消正在解码的邻页。 |
| 双端缩放还原短闪 | PC 除重采样本身，还存在画布先清空、可见状态稍后更新，以及新像素先到、旧映射后改的交接空窗。改为同一次显示提交内完成，运动时保留已有画面，相同最终尺寸复用已有结果。Android 还原时固定已经完整显示的高清分块，沿同一几何缩小，结束后在 120 ms 内淡出到适屏底图，避免动画途中反复切换分块质量。 |
| 手机放大后不能连续拖到下一页 | 单指先平移当前图片，达到水平边界后把超出的位移交给分页；相邻页从对应边缘进入，翻页后保留放大比例。支持单页、双页和从右到左阅读。快速松手遇到未准备完整的双页时保留当前姿态，准备好后完成翻页；等候可被新手势接管，失败会回弹。 |

按本次追加要求，核对官方 `neelabo/NeeView` 的固定 revision `686a43362dc4b3c9f2ea014240dbba2d0e9fbcaa`，相关源码保存在 `.cache/neeview-1154/`。

- `NeeView/PageFrames/PageFrameBoxDelayMove.cs` 的 `MoveToAsync` 先请求目标范围加载，等待 `container.WaitLoadAsync(token)`，再在界面线程执行移动。
- 同时查看了 `PageFrameContainerFiller.cs`、`PageFrameContainerCleaner.cs`、`ViewContent.cs`、`ImageViewContentStrategy.cs` 和 `ImageContentControl.cs`，用于核对加载、内容建立和展示之间的边界。
- 本轮采用“目标内容真正准备好后交接”的设计原则，使用 Omi 既有的页组、画布、取消和缓存流程实现，没有直接搬入 C# 业务代码。此前 EhViewer 的时序来源说明与 Apache 2.0 许可继续随包保留。

用户关于“旧优化未对接”的判断在 PC 往返翻页上成立。修改前的工作区副本已通过往返测试复现空帧，修复后同类测试通过。由于前序多轮修改尚未形成独立提交，本报告不把回归归咎于某个未经验证的历史提交。

## 性能取舍

没有把 Android 原生解码并发从 4 增加到 8，也没有提高内存预算。提高并发会同时增加解码任务占用的 CPU 和临时内存，不能直接等同于更快显示。本轮优先缩短已完成结果的等待时间，防止近页被远页挤出缓存。

32 ms 是有新结果时的合并发布间隔，不是每 32 ms 全量刷新。还原复用现有高清分块，不新建整屏快照，也不为中间比例追加分块解码；120 ms 淡出只延长这些现有像素的短暂使用。整体收益仍取决于图片大小、压缩格式、存储速度和设备；尚未进行真实手机的长时间功耗测试。

## 验证

- 类型检查通过。显示取样、画布生命周期与原生几何测试共 22 项通过。
- 阅读浏览器回归覆盖 40 个不同用例：本轮画面交接 11 项、1.1.53 动作回归 16 项、物理像素对齐 4 项、1.1.52 交互回归 9 项。记录见 `output/reader-1154/regression-second.log`、`jump-align.log` 和 `presentation-final.log`；部分用例在不同轮次重复执行。
- 实际 Windows 打包 EXE 使用独立数据目录验证：最终包往返翻页记录 570 帧，空白帧和尺寸错配均为 0；横、纵全景进度跳转最终画布尺寸误差为 0；普通／横向全景／纵向全景各测试缩小及放大还原，共 6 组，均有连续中间比例，空白帧为 0。结果为 `output/reader-1154/packaged-motion.json`。
- Android APK 的版本、签名、四架构原生库、16 KB 对齐和打包网页摘要已核对。原有签名保持一致，可覆盖安装。静态校验为 `test-results/android-artifact.json`。
- 实际 Android APK 在专用 Android 15 模拟器 `emulator-5580` 上通过：普通／全景各测试放大和缩小还原，共 4 组，分别记录 12、7、11、11 个原生中间比例，所有记录帧均有图片，空白帧计数均未增加。两组放大还原分别记录 14、13 帧保留高清分块，随后淡出到适屏底图。
- 手机普通单页／双页／反向双页的完成动画分别记录 20、34、34 个不同原生位置；约 257% 放大时，三种模式均能先平移到边缘，再连续拖到相邻组并保留比例。首尾阻尼、短拖回弹、还原后拖动继续通过。
- Android 全景慢拖记录 26 帧，固定页面的宽高及垂直于拖动方向的位置保持一致，原生近页优先集合已建立，无新增空白帧。测试结束时，底图加分块约 28.7 MiB，设备给予的对应预算为 64 MiB，取消加载数为 0。这验证了本次测试场景，不能当作真机长时间性能或功耗结果。完整记录为 `test-results/android-presentation1154.json`。
- 验收工具补充了失败后清理残留触点、只记录实际原生绘制变化的处理，避免重复运行时触点仍按住，或大量空闲帧超出测试结果传输上限。这些处理只属于测试程序。
- 前序已知的普通阅读鼠标边缘点击测试，在 1.1.53 修改前的工作区文件上也失败。本轮未将它算作通过，也未扩大修改范围；对照记录为 `output/reader-1153/stability-baseline.log`。
