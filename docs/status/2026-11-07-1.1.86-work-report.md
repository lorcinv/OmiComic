# OmiComic 1.1.86 工作报告

后续更正：用户随后反馈较大松手坐标校正仍会回滚，切换全景也有颤动，PDF 快滑存在重复绘制。已在 [1.1.87 修复报告](2026-11-07-1.1.87-work-report.md) 补充复现与修复。下文保留当时的测试记录；当时通过的单次拖动检查没有覆盖这些情况。

日期：2026-11-07。Android 版本 **1.1.86 / 10186**，沿用原签名；Windows 成品保持 1.1.85。本轮已完成本地修改、构建和验证，没有提交、推送或公开发布。

## 本轮结果

- EPUB 书目与章节共享一次 ZIP 目录索引，减少重复遍历。保留 1.1.85 的首屏准备、延后分页和入场动画。其他格式没有证实稳定的提速空间，因此保留已有加载路径。
- 手机和平板全景模式：慢拖保持精确，快拖渐进加速，快速松手滑行更远；按下即可止动，反向操作及时接管。
- 全景漫画延伸到原来预留的顶部和侧边挖孔区域。工具栏、底部进度栏、页码及阅读设置独立避让；显隐工具栏不改变漫画窗口，退出阅读恢复资源库安全区域。
- 交付最终 APK、对应源码、报告、原始结果及截图。工作区已有大量未提交改动，本轮没有清理或覆盖其他工作；本次生产改动单独记录为 `验证/production-changes.patch`。

## ComicScreen 对照

使用 REA 核验用户提供的 APK，并复用项目已有解包结果。ComicScreen 的连续阅读实际走 RecyclerView：按触点位移拖动，VelocityTracker 计算释放速度，OverScroller 负责惯性，新手指按下接管滚动。没有证据表明其普通连续拖动另有加速倍率；Omi 的渐进倍率是针对本次需求做的调整。

其隐藏系统栏和扩展到挖孔区域是两个独立设置，旋转后会重新应用。Omi 据此分开处理漫画画面和控件安全区域。完整证据、定位及限制见 [ComicScreen 分析](2026-11-07-comicscreen-panorama-analysis.md)。REA 方法接口缺少配置，方法分析使用现有 JADX 文件；本次没有运行 ComicScreen，也没有宣称两款软件的性能高低。

## 启动速度：测得什么，保留什么

设备为同一 Android 15 x86_64 模拟器，WebView 124；基线是已有 1.1.85 EPUB 热修复 APK。以下 EPUB 读数为一次预热后七轮的中位数，单位毫秒。“首章”包含打开文档与读取第一章；“合计”包含打开文档与首、中、末三章读取，不包含排版、解码和入场动画。

| 合成测试书 | 打开并读取首章：旧 → 新 | 读取末章：旧 → 新 | 打开及三章合计：旧 → 新 |
| --- | ---: | ---: | ---: |
| Text.epub | 3.7 → 3.6 | 1.5 → 1.1 | 6.7 → 6.2 |
| StartupPictures.epub | 6.5 → 6.3 | 3.2 → 2.0 | 11.8 → 10.5 |
| StartupDeep.epub | 39.1 → 28.2 | 16.7 → 0.7 | 69.9 → 30.0 |

1200 章样本的首章准备缩短约 28%，末章直接定位收益更明显。小书首章差异很小，不能当作普遍可感知提速。文本章节内容摘要核对一致；图片章节中的会话媒体地址会变化，不将整段 HTML 摘要差异当作内容损坏。

实现限定在 Android EPUB：`ZipArchive.openDocument` 为会话建立有上限的目录；container.xml、OPF 和章节共用索引。每次读取仍检查长度与 CRC。不支持的 ZIP 压缩方式及旧文件名编码沿用 libarchive；选中条目后发现损坏会报错，不用回退掩盖损坏。关闭文档时释放索引。PDF、MOBI、图片、ZIP/CBZ、RAR/CBR、7Z/CB7 的既有读取路径没有调整。

## 全景拖动

触摸速度统一按 CSS 像素计算，以适应不同屏幕密度。慢拖倍率为 1；快拖平滑增加，最高 1.65。释放速度取最近 80 毫秒有效轨迹，快甩的衰减时间从 240 毫秒平滑增加至最多 400 毫秒，速度上限维持原值。桌面鼠标沿用原参数。

前后对照使用相同的慢拖 100、快拖 220 CSS 像素输入；惯性取释放后约 550 毫秒的位置差。以下是手机三个方向的一次代表性对照，不是触摸延迟或帧率统计。

| 方向 | 慢拖期间位移：旧 → 新 | 快拖期间位移：旧 → 新 | 快拖松手后位移：旧 → 新 |
| --- | ---: | ---: | ---: |
| horizontal | 99.9 → 99.9 | 177.5 → 233.1 | 420.6 → 583.3 |
| vertical | 99.9 → 99.9 | 177.7 → 255.3 | 450.1 → 664.1 |
| rtl | 99.9 → 99.9 | 189.3 → 242.3 | 389.3 → 575.6 |

验证覆盖横向、纵向、从右到左阅读，以及按下止动、取消拖动、反向后停留再松手。真实 WebView 会在最后一帧 MOVE 外推坐标，UP 再校正；本轮曾复现松手倒滑，现用足够位移的方向变化区分主动反向和小幅校正，并补了回归测试。

## 手机和平板适配

最终包在四种窗口配置下分别检查三个阅读方向。横屏通过 Activity 真实旋转，并断言挖孔移动到侧边，避免仅交换窗口尺寸造成假覆盖。表中的视口为退出阅读后的 CSS 尺寸，挖孔为阅读中 Android 返回的物理像素。

| 配置 | 视口 | 挖孔上／左／右 | 三方向、按钮边界、设置面板、退出恢复 |
| --- | --- | --- | --- |
| panorama-phone | 412 × 632 | 136 / 0 / 0 | 通过 |
| panorama-phone-landscape | 632 × 388 | 0 / 136 / 0 | 通过 |
| panorama-tablet-portrait | 800 × 1134 | 181 / 0 / 0 | 通过 |
| panorama-tablet-landscape | 1190 × 744 | 0 / 181 / 0 | 通过 |

顶部挖孔区域不再作为整幅漫画的内边距，工具栏仍保留必要的安全位置。横屏进度栏使用左右边界收缩可用宽度；已修正“左侧加边距但仍保留 100% 宽度”导致播放按钮出屏的问题，并在修复前复现、修复后通过边界断言。最终截图还检查了工具栏与底栏完整显示、漫画延伸至顶部／侧边、控件隐藏后的正文画面。
