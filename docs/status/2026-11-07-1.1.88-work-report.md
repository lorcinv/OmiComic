# OmiComic 1.1.88 放大拖动惯性工作报告

2026-11-07。Windows 与 Android 均更新至 1.1.88，Android 版本码 10188。本轮为本地交付。

## 完成内容

图片放大后，拖动仍直接跟随鼠标或手指；松开后根据最近的拖动速度继续滑行并逐渐减速。普通阅读支持横纵两轴，全景沿阅读方向保留既有滚动，新增垂直于阅读方向的放大平移惯性。

- 新按下立即停止惯性；主动反向拖动按新方向释放。
- 停顿后松手不续滑，拖动到边界时分别停止对应方向，不反弹，不由惯性触发翻页。
- 多指缩放、Ctrl＋滚轮、重置、换页、窗口变化、失去焦点、退出阅读都会停止旧任务。
- 手机边缘翻页与放大拖动各自接管释放，防止同时开始翻页和图片惯性。
- 防止系统松手坐标校正引发反向滑行；速度采样与松手停顿分开处理，避免释放事件稍迟就丢掉有效拖动速度。
- 区分点击止动与正常双击重置，防止快速接管时意外恢复原图大小。

实现集中在 `src/hooks/useReaderZoom.ts` 与阅读页的手势交接。没有修改文档解析、页面解码、缓存预算、全景主方向惯性或系统安全区域策略。手机、平板和 Windows 使用相同的屏幕坐标速度单位。

## 前后对照

同一 Android 15 x86_64 模拟器、WebView 124，使用同尺寸的合成 CBZ／PDF，普通阅读、横向全景、纵向全景各一组。输入为放大至约 3 倍后拖动约 90 CSS 像素，并在 UP 加入 35 像素反向坐标校正。

为排除最后一帧拖动的提交延迟，统计松手后第 50–180 ms 内继续移动的距离：

| 手机竖屏 | 1.1.87 | 最终 1.1.88 |
| --- | ---: | ---: |
| CBZ 普通阅读 | 0 | 16.03 px |
| CBZ 横向全景 | 0 | 18.70 px |
| CBZ 纵向全景 | 0 | 21.90 px |
| PDF 普通阅读 | 0 | 25.56 px |
| PDF 横向全景 | 0 | 12.58 px |
| PDF 纵向全景 | 0 | 24.10 px |

这些数据确认松手续滑已生效，不是帧率或整体提速对比。各组实际输入间隔由模拟器调度，不能把距离差用于比较格式性能。平板横屏六组均有同向续滑；按下止动、停顿后松手、不误翻页与原生画面持续存在检查通过。

- 类型检查、Android 与 Windows 构建通过。
