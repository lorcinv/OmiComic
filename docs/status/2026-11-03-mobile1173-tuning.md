# 1.1.73 手机预览与开书响应补充修复

2026-11-03，Asia/Hong_Kong。仅修改手机对应行为，不更新版本：package / desktopVersion / Android versionName 仍为 1.1.73，versionCode 仍为 10173。新包独立保存于 `release/OmiComic-1.1.73-手机体验优化版/`，原 Windows 和 Android 包保留。

## 修改

- 手机预览条由用户滑动持续接管位置。普通、横向全景和纵向全景的延迟正文回报不能重新定位它；点击正文、使用音量键或主动操作进度条时交还控制。外部翻页只保证目标缩略图进入中央容差范围，允许约一张缩略图的偏移，不锁定正中心。
- 缩略图窗口和选中框实时跟随真实滚动；正文导航合并到每 100 ms 最多一次，停稳后补齐最终页，避免每跨过一张缩略图都重启正文准备。预览继续使用系统原生横向惯性。
- 手动滚动时提前准备行进方向的少量小图，优先当前位置与前方邻图。复用原有 64 项 / 8 MiB 解码缓存，没有增加磁盘缓存上限；静止打开和主动跳页不额外预取。
- Android PDF 的小预览等待正文最多 48 ms，随后允许小预览继续准备，避免连续翻页时一直排队；优先复用正文已有画面。邻页解析窗口从 2 页扩到有界的 6 页，减少往返拖动时重复解释页面，PC 保持原有参数与路径。
- 点击漫画时先用已经显示的封面启动原生展开，文件清单、阅读模块和正文准备在后台同时进行。只复制已解码封面的有界小图，不截入卡片按钮，也不为开书等待整屏截图。展开为 180 ms，正文真正就绪后通过短暂交接显示，不再补一次完整进入动画。其他栏目和首页的动画时长保持原有规则。
- 加载期间返回、失败、切换资源、后台暂停都释放封面过渡；取消代号阻止已取消的迟到结果重新打开漫画，也防止旧请求清理掉新请求。

## PDF 为什么更慢

压缩漫画通常只需取出图片并解码。PDF 还要定位页面、解析字体与绘图指令，再把嵌入图片和其他内容绘制成页面。复杂 PDF 的这些成本不会因为体积小就消失。原路径的小预览还会等待正文结束，快速拖动时反复准备正文会扩大这段等待。本次减少互相等待与重复解析，并让点击动画独立于文档处理开始；不把封面动画出现的时间当作 PDF 正文解码完成的时间。
