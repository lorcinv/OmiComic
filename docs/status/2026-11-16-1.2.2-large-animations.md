# 1.2.2 大体积动图修复与验证

日期：2026-11-16。状态：测试包，未发布 GitHub Release，未合并 main。

对应反馈：[Android 大 GIF 无法打开，Issue #6](https://github.com/lorcinv/OmiComic/issues/6)。

## 修复内容

- Android 原先将单张图片限制为 64 MiB，压缩包索引还会直接跳过超限图片。GIF、动态 WebP、APNG 现在通过有界流读取，单张上限为 256 MiB；旧压缩包索引会失效重建，不再漏掉大图页。
- Android 原生层只读取动画类型与尺寸，将原始动画交给 WebView 播放。普通静态图片继续使用原生解码与原有 64 MiB 限制。
- Android 封面只提取首帧，避免系统缩略图解码器扫描整段动画、阻塞后续切书。首帧容器最多 64 MiB，解码前仍按封面尺寸采样。
- Windows/macOS 的普通图片与漫画压缩包原已支持 256 MiB。此次修复 EPUB 单张 8 MiB 内嵌图片限制：大动图使用阅读会话内的本地流式地址，关闭书籍即失效，不再转换为巨大的 Base64 字符串或静默丢弃。
- 保留图片尺寸、条目总量、展开大小、校验与路径限制；流读取支持取消，错误和退出时释放文件及压缩包句柄。超过 256 MiB 的图片明确提示大小上限。

## 样本与验证方式

先在 1.2.1 重现 Android 66 MiB GIF 无法显示、桌面 EPUB 大 GIF 被丢弃，再对修复包检查实际画面变化。

- GIF、WebP 使用约 66 MiB 的合法容器填充样本，验证文件大小与读取边界；不以填充字节代表复杂动画解码压力。
- APNG 最终本地样本为 512 × 512、90 个完整图像帧，约 67.6 MiB。Mac CI 使用前一版约 66 MiB 的合法附加块样本；两者均保留连续动画帧。
- 真实 GIF 使用 [Wikimedia 的 Hurricane Lorenzo 动画](https://upload.wikimedia.org/wikipedia/commons/f/ff/24_hours_in_the_life_of_Major_Hurricane_Lorenzo_%28CIRA_2019-09-27%29.gif)，1024 × 768，68,989,191 字节（65.8 MiB），在 Windows 和 Android 检查实际播放。
- 目录、ZIP/CBZ、EPUB 覆盖 GIF、动态 WebP、APNG；另测大 GIF 的 7z/CB7，桌面额外覆盖图文混排 EPUB。
- 动图打开后采样画面像素，切到静态页再返回重新采样。桌面额外检查全景播放，Android 的 CBZ 用例在全景模式下往返翻页；静态页仍走原生通道。
