# 1.1.67 漫画开书、全景进度和结构检查

2026-11-01，Asia/Hong_Kong。基于 1.1.66 本地工作区增量修改。编辑前源码快照位于被忽略的 `.cache/entry-1167/before/`；工作区仍保留多轮未提交修改，未重置、清理或全量暂存。

## 对应用户问题

| 问题 | 原因及本版处理 |
| --- | --- |
| 手机已开启全景的漫画进入较慢 | 全景仍同时执行普通单双页加载流程，保存双页时会准备不可见配对页；初始尺寸未知也会干扰邻页判断。全景统一由可见页通道处理，先取得当前页尺寸再补真正可见的邻页，首屏后再预读。 |
| PC 开书加载闪动、双页更明显 | 阅读器提前显示后，临时加载卡片和先完成的一张图片暴露出来。本版保留界面提前进入，只在实际 DOM 图像完成解码、整组布局确定后显示首屏；慢读取 180 ms 后显示一处轻量状态，错误与重试保留。绘制门槛使用独立属性，避免全景动画清理覆盖它。 |
| 手机拖进度条画面不跟随 | 实际触摸复现了 DOM 索引已更新而原生画面还在旧位置。远距拖动立即更新原生读取代次、取消无用读取；原生在持续拖动时及时显示目标位置已准备好的清晰页，不再因边缘未完成而保持无关旧页。未缓存内容仍需要读图，未改用模糊缩略图。 |
| 设置名称 | PC 和手机均显示“默认开启全景连环画模式”，同步翻译键。 |
| 默认状态 | 两端新建资料原本已为全景关闭、单页、从左到右。本版补上持久化回归，确认重新加载仍正确，显式选择和单本进度不会被默认值覆盖。 |
| 结构和速度空间 | 检查源码分布及开书、任务队列、首帧、缓存与持久化边界；本版修复重复读取和重复系统全屏请求，后续候选见下文。 |

首屏前仍优先当前可见内容，后台预读预算、并发限制、原图适屏处理、原像素放大、取消和超时规则保留。手机原有进入、返回和全景跳页动画保留。进入与普通翻页仍要求完整清晰帧；进度拖动期间未准备的边缘不阻挡已准备的目标清晰页，松手后继续补齐。

## 手机开书对照

专用 Android 15 模拟器、同一合成 Color.cbz（2400×3200）、实际触摸进入、原生帧记录，每模式 3 次取中位数。前版为实际 1.1.66 APK，后版为最终 1.1.67 APK。数字包含触摸注入与探针开销，系统与文件缓存未强制清空，不能作为真机绝对延迟或统一提速比例。

| 模式 | 1.1.66 | 1.1.67 |
| --- | ---: | ---: |
| 普通单页 | 592 ms | 516 ms |
| 普通双页 | 829 ms | 594 ms |
| 全景单页设置 | 609 ms | 505 ms |
| 全景保留双页设置 | 未单独测量 | 520 ms |

共检查最终 APK 12 次进入，必须有原生滑入动画中间帧，保存位置保持第 5 页，检查未暴露空的原生首屏。全景保留双页设置时，首屏前只请求当前页，不再等待不可见配对页。每次有一次 App 提前预热和一次阅读器订阅；两者通过原生共享任务复用，不把请求条数当作实际解码次数。

进度条检查覆盖横向、纵向、从右到左，每种在 3 个位置持续按住，核对 DOM 中心页、滑块捕获和实际原生图片 URL 一致。未缓存的大图仍有读取时间，本版解决的是画面停留在无关旧位置和无用任务抢占。旧版固定 350 ms 观察与新版持续等待的探针条件不同，不对这两份记录计算延迟改善比例。

## 结构检查

本轮清点 `src`、`electron`、`android/src` 下 175 个 TypeScript / TSX / Java 文件，重点阅读开书和显示链路。结果与文件行数写入 `structure-review.json`；清点不等于对全部代码逐行完成正确性证明。

| 边界 | 当前结构与结论 |
| --- | --- |
| 首页 / 资源库 → 清单 | 已复用阅读器模块预热；清单携带最新设置和阅读进度。保留异步取消和排序一致性。 |
| App → 阅读器 | PC 立即进入界面，手机准备后按原动画转场，进度在允许时才写入。重复系统全屏请求已合并成初始化时一次。 |
| 阅读器页面与调度 | `ReaderPage.tsx` 同时承担几何、普通页、全景、手势和持久化，约 4,500 行。本版使全景前台读取只由一个通道拥有，避免与普通页组相互覆盖。 |
| Android 原生 | JS 传几何，原生保留清晰位图；全景平移和远距进度定位需要不同的取消策略。本版仅为远距进度定位引入及时换代，普通连续拖动保持现有调度。 |
| PC 解码 / 显示 | 有共享压缩包读取、解码字节预算、实际 DOM 解码检查和后台适屏副本。保留这些约束，不以提高并发或降低分辨率换速度。 |
| 缓存 / 数据 | 预读窗口已按内存约束移动，读写资料已有原子快照与串行写入。本轮未改缓存预算、数据格式和文件读取实现。 |

仍有三项后续空间：逐步拆出大型阅读器 / 资源库组件的纯计算和任务生命周期；建立可验证失效规则的图片尺寸缓存以减少首次几何修正；测量桌面预解码与 DOM 校验是否共享底层解码结果。后两项需要真实文件和设备记录支持，本版没有贸然删除解码门槛或进行大范围重构。
