# OmiComic 1.1.37 双端校验记录

2026-10-18 · 本地交付 · [完整校验数据](releases/verification-1.1.37.json)

“最近阅读”已改为圆形时钟，只保留表盘和指针。Windows、Android 使用同一图标组件。

本轮检查覆盖桌面 IPC 和文件访问授权、路径边界、保存事务、压缩包读取限额、PDF 范围读取、EPUB 内容隔离，以及 Android 文件授权、原生索引、阅读器缓存和后台恢复。

## 已修复的问题

- **桌面保存失败后的状态残留。** 原实现在写盘失败前已经改动公共内存对象，失败的阅读进度可能被下一次保存带入磁盘。现在每次变更使用独立草稿，原子写入成功后才公开；慢速保存期间读取仍返回已提交的数据。新增测试先复现问题，再验证失败后的磁盘、内存和后续保存。
- **取消打开文档后的会话残留。** 用户退出后，较慢的原生打开操作仍可能创建会话。现在操作返回时检查关闭状态，立即释放迟到的会话；PDF、EPUB 都有回归测试。
- **安卓归档文件名缺少总量限制。** 修复前可打开 4,097 个字符的路径样本。现在单路径最多 4,096 个 UTF-16 代码单元，单个归档索引的文件名 UTF-8 总量最多 8 MiB，缓存索引按 16 MiB 文件名总量淘汰；读取缓存索引也执行限制。五种恶意样本均被拒绝，合法边界和缓存复开通过，普通归档读取流程保持原样。

## 加载优化

PDF 引擎改为只在打开 PDF 时加载，且和原生文件打开同时开始。EPUB 不再加载这部分代码：Windows 少加载 482,617 字节，Android 少加载 540,755 字节；共用文档入口为 5,502 字节。已验证拦截全部 PDF 模块请求时，EPUB 仍能打开和翻章。

关闭模拟器和其他测试后，原版、修改版交替运行，各用五个独立配置测量。文档模块导入中位数从 **21.6 ms 降至 1.3 ms**；空书库首页就绪中位数为 **468.9 → 444.9 ms**，本次对照未见启动退化。这是 Windows 隐藏窗口、热文件缓存的本机对照，不代表完整大书冷打开或安卓真机耗时。此前不同负载下的分开计时不用于比较。

## 依赖审计

生产 npm 依赖的已知漏洞告警为 **0**。完整开发依赖树仍有 8 个中危包节点，均来自同一项 [sprintf-js 格式精度导致拒绝服务的上游告警](https://github.com/advisories/GHSA-hp3w-g68c-fv3c)，没有高危或严重告警。受影响路径属于 electron-builder 打包工具；已核对 sprintf-js、roarr、global-agent 不在应用运行包中。

该告警尚无已修补版本。审计工具建议回退 electron-builder 至 26.5.0，本轮保留现有打包工具，避免为仅涉及构建的告警改动已验证的打包链。以上结论针对本次源码审查、依赖审计和实际回归覆盖。
